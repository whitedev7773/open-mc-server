# Open MC Server

**싱글플레이 월드를 열고, 공개방 목록에서 찾아, 한 번의 클릭으로 함께 플레이하기.**

Open MC Server는 Minecraft에서 별도 서버 구축, 포트 포워딩, IP 주소 공유 없이 자신의 싱글플레이 월드를 공개하고 다른 플레이어가 참여할 수 있도록 구상한 프로젝트입니다. Minecraft 모드, 방 목록을 관리하는 백엔드, 게임 트래픽을 중계하는 Relay 네트워크로 구성됩니다.

> **개발 상태:** 현재 이 저장소는 기획 단계입니다. 아래 기능과 구조는 구현 완료 사항이 아닌 목표이며, 실행 가능한 배포본과 설치 방법은 아직 제공하지 않습니다. 상세 설계는 [PLAN.md](PLAN.md)를 참고하세요.

## 사용 경험

1. 호스트가 싱글플레이 월드에서 **공개방 열기**를 선택하고 방 이름, 최대 인원 등을 설정합니다.
2. 방이 중앙 목록에 등록됩니다.
3. 다른 플레이어가 목록에서 방을 선택하고 **참가**를 누릅니다.
4. 인증과 연결 절차가 자동으로 진행되어 같은 월드에서 플레이합니다.

0.1은 Minecraft Java Edition과 Fabric의 검증된 단일 버전 조합을 대상으로 하며, 호스트와 참가자 모두 모드를 설치합니다. 정확한 버전은 초기 연결 실험에서 확정합니다. 호스트 PC가 월드를 실행하므로 호스트가 게임을 종료하면 참가자의 플레이도 종료됩니다.

초기 목표는 방 생성·종료, 목록·상세 조회, 원클릭 참가, 기본 버전 검사, 월드 백업 선택, 킥·지속적인 밴·신고입니다. 검색·필터, 비공개방, 방 코드, 친구·초대, 고급 모드 호환성 확인은 후속 단계로 계획하고 있습니다.

## 설계 방향

```text
호스트의 Minecraft 모드 ── 암호화된 터널 ── Relay ── 암호화된 터널 ── 참가자
               │                                             │
               └──────── 방 등록·인증·참가 요청: 백엔드 ────────┘
```

- **Minecraft 모드:** 싱글플레이 월드 공개, 방 탐색·참가, 호스트의 방 관리 UI를 담당합니다.
- **Control Backend:** 검증된 Minecraft 계정과 게임 접속 신원을 연결하고, 방 목록·상태, 참가 티켓·정원 예약, Relay 배정, 신고와 이용 제한을 관리합니다.
- **Relay Network:** 호스트와 참가자 사이의 Minecraft 트래픽을 중계합니다. 공개방 연결에는 직접 P2P 연결을 사용하지 않는 방향입니다.
- **운영 도구:** 신고 처리, 서비스 상태 확인, 남용 대응을 지원하도록 계획하고 있습니다.

IP 보호를 핵심 원칙으로 삼습니다. 서비스가 관리하는 API와 게임 연결 경로에서는 상대 플레이어에게 실제 IP와 로컬 게임 포트를 전달하지 않습니다. Relay 운영 인프라는 접속 IP를 처리하며, 초기 암호화 보장은 각 사용자와 Relay 사이의 구간 암호화입니다. 외부 리소스팩·음성 모드 등 별도 통신까지 보호한다고 보장하지 않습니다.

참가에는 짧은 유효 기간의 일회용 Join Ticket을 사용하고, 호스트 연결에는 별도 토큰을 사용합니다. 티켓 소비와 정원 예약을 함께 검증하고 실제 게임 로그인 신원과 비교합니다. 목록에서 방을 숨기는 상태와 게임 연결 수명을 구분하며, Backend만 일시 중단된 경우 기존 연결을 마지막 승인 후 최대 120초 유지하는 초기 정책을 두었습니다. 시간·용량 수치는 실제 실험 후 조정합니다.

0.1 공개 알파는 한 지역의 제한된 수용량으로 시작하며 고가용성을 약속하지 않습니다. 기본 모니터링·알림, 비용 한도, 신고 처리·밴, 개인정보 삭제와 장애 대응은 공개 전에 준비합니다.

## 이전 프로젝트와의 관계

Open MC Server는 [kfcudp-instant-p2p](https://github.com/KITE2459/kfcudp-instant-p2p)의 **정신적 후속작**입니다. 싱글플레이 월드를 간편하게 다른 사람과 공유한다는 목표를 이어받았습니다. 이전 프로젝트가 초대 코드와 WebRTC 기반 P2P 연결에 초점을 맞췄다면, 이 프로젝트는 **공개방 탐색과 원클릭 참가**, **Relay를 통한 IP 보호**를 중심으로 새롭게 설계하고 있습니다. 기존 프로젝트의 코드나 프로토콜을 그대로 계승한다는 뜻은 아닙니다.

## 개발 계획

| 단계 | 목표 |
| --- | --- |
| 핵심 실험 | 계정 소유 검증, 지원 버전 확정, Integrated Server와 Relay를 통한 실제 플레이 |
| 승인·상태 기반 | 티켓·정원 예약, Room 생명주기, 지속적인 밴, 종료·장애 복구 |
| 최소 사용자 흐름 | 목록·생성·참가·종료 UI, 백업, 기본 관리와 오류 안내 |
| 공개 알파 준비 | 동시성·장애·성능 검증, 운영 도구, 모니터링, 개인정보 삭제, 비용·수용량 산정 |
| 0.2~0.4 | 검색·비공개방, 친구·초대, 고급 모드 호환성 순차 추가 |
| 1.0 | 복수 Relay·다중 지역, 자동 용량 배정, 운영 신뢰성 확장 |

첫 공개 테스트 버전인 **0.1 MVP**의 범위는 [버전별 계획](PLAN.md#39-publicroom-01-mvp), 인증·지원 버전·배포의 미확정 사항은 [결정 기록](PLAN.md#47-구현-전-결정-기록과-미확정-항목), 출시 조건은 [검증 기준](PLAN.md#48-검증과-출시-완료-기준)에 정리되어 있습니다. 기술 스택과 저장소 구조는 계획안이며, 실제 구현과 시험 결과는 아직 없습니다.
