# Open MC Server

**싱글플레이 월드를 열고, 공개방 목록에서 찾아, 한 번의 클릭으로 함께 플레이하기.**

Open MC Server는 Minecraft에서 별도 서버 구축, 포트 포워딩, IP 주소 공유 없이 자신의 싱글플레이 월드를 공개하고 다른 플레이어가 참여할 수 있도록 구상한 프로젝트입니다. Minecraft 모드, 방 목록을 관리하는 백엔드, 게임 트래픽을 중계하는 Relay 네트워크로 구성됩니다.

> **개발 상태:** 현재 이 저장소는 기획 단계입니다. 아래 기능과 구조는 구현 완료 사항이 아닌 목표이며, 실행 가능한 배포본과 설치 방법은 아직 제공하지 않습니다. 상세 설계는 [PLAN.md](PLAN.md)를 참고하세요.

## 사용 경험

1. 호스트가 싱글플레이 월드에서 **공개방 열기**를 선택하고 방 이름, 최대 인원 등을 설정합니다.
2. 방이 중앙 목록에 등록됩니다.
3. 다른 플레이어가 목록에서 방을 검색하고 **참가**를 누릅니다.
4. 인증과 연결 절차가 자동으로 진행되어 같은 월드에서 플레이합니다.

초기 목표는 방 생성·종료, 목록 조회, 방 정보 확인, 원클릭 참가, 기본적인 킥·신고 기능입니다. 검색·필터, 비공개방, 방 코드, 친구·초대, 모드 호환성 확인 등은 후속 단계로 계획하고 있습니다.

## 설계 방향

```text
호스트의 Minecraft 모드 ── 암호화된 터널 ── Relay ── 암호화된 터널 ── 참가자
               │                                             │
               └──────── 방 등록·인증·참가 요청: 백엔드 ────────┘
```

- **Minecraft 모드:** 싱글플레이 월드 공개, 방 탐색·참가, 호스트의 방 관리 UI를 담당합니다.
- **Control Backend:** Minecraft 계정 인증, 방 목록과 상태, 참가 티켓, Relay 배정, 신고와 이용 제한을 관리합니다.
- **Relay Network:** 호스트와 참가자 사이의 Minecraft 트래픽을 중계합니다. 공개방 연결에는 직접 P2P 연결을 사용하지 않는 방향입니다.
- **운영 도구:** 신고 처리, 서비스 상태 확인, 남용 대응을 지원하도록 계획하고 있습니다.

IP 보호를 핵심 원칙으로 삼습니다. 참가자에게 호스트의 IP와 포트를 전달하지 않고, 호스트도 참가자의 IP를 직접 알 필요가 없도록 설계합니다. 참가에는 짧은 유효 기간의 일회용 Join Ticket을 사용하고, 호스트의 Relay 연결에는 별도 토큰을 사용합니다. 방은 heartbeat 기반으로 상태를 확인하며, 종료되거나 만료되면 참가와 세션을 정리합니다. 인증, 속도 제한, 트래픽 제한 및 신고·차단 기능도 함께 계획하고 있습니다.

## 이전 프로젝트와의 관계

Open MC Server는 [kfcudp-instant-p2p](https://github.com/KITE2459/kfcudp-instant-p2p)의 **정신적 후속작**입니다. 싱글플레이 월드를 간편하게 다른 사람과 공유한다는 목표를 이어받았습니다. 이전 프로젝트가 초대 코드와 WebRTC 기반 P2P 연결에 초점을 맞췄다면, 이 프로젝트는 **공개방 탐색과 원클릭 참가**, **Relay를 통한 IP 보호**를 중심으로 새롭게 설계하고 있습니다. 기존 프로젝트의 코드나 프로토콜을 그대로 계승한다는 뜻은 아닙니다.

## 개발 계획

| 단계 | 목표 |
| --- | --- |
| 프로토타입 | Fabric 모드 기본 구조, UI, Integrated Server 연결 검증 |
| 공개방 기반 | 방 목록·생성 UI, 방 API, heartbeat |
| 연결 기반 | Relay 중계, Join Ticket, 자동 참가 |
| 보안 MVP | 계정 인증, 토큰 검증, 재사용 방지, 속도·세션 제한 |
| 공개 알파 이후 | 검색·운영 도구, 다중 Relay, 친구·초대, 호환성 확인 |

첫 공개 테스트 버전인 **0.1 MVP**의 범위와 이후 버전별 기능은 [PLAN.md](PLAN.md#39-publicroom-01-mvp)에 정리되어 있습니다. 기술 스택과 저장소 구조 역시 계획안이며 개발 과정에서 바뀔 수 있습니다.
